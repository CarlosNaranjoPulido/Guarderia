## Project: open-guarderia

Spanish-language daycare/guardería app built on Next.js. Currently a bare create-next-app scaffold: `app/` contains only the home page; there is no backend, database, auth, or feature code yet.

## Commands (run from `open-guarderia/`)

- `npm install`
- `npm run dev` → http://localhost:3000
- `npm run build` → `next build` (Turbopack); runs TypeScript check internally. Must pass before finishing feature work.
- `npm run lint` → runs `eslint` (flat config `eslint.config.mjs`, `eslint-config-next`). **Currently exits 1** due to pre-existing errors in `references/pantallas/support.js` (deprecated `ReactDOM.render`, module assignment) — design-prototype code, not app code. Don't treat those as regressions from your work; check whether lint errors touch your changed files.
- Typecheck: `npx tsc --noEmit` (no `typecheck` script exists).

### Suggested verification order

`npx tsc --noEmit && npm run lint && npm run build` (build already includes a TS pass, but run `tsc --noEmit` when you only changed types).

## Toolchain quirks

- Next.js **16.4.3** — treat `node_modules/next/dist/docs/` as the source of truth before writing code; heed deprecation notices. Do not rely on pre-16 Next.js knowledge.
- `next.config.ts` enables `experimental.agentFeedback`, `cacheComponents: true`, `partialPrefetching: true`, and a Turbopack CSS rule (`@tailwindcss/turbopack`).
- Path alias: `@/*` → `./*` (repo root, not `./src`).
- `next-env.d.ts` is gitignored but generated by Next (dev/build) and pulls in `.next/dev/types/*` route types during dev.

## Testing / browser checks

- No test framework, runner, or scripts configured (no jest/vitest/playwright config). `playwright` is a devDependency plus a local MCP server configured in `opencode.json` (`npx @playwright/mcp@latest --browser chromium --headless`).
